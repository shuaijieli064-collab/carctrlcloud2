# HI3861 编译环境搭建手册（马老师版 · 最短路径）

> 目标：在本机搭好 OpenHarmony 5.0.0 轻量系统（hi3861）编译环境，跑通
> "改代码 → 编译 → 烧录小车"闭环，最后打包成镜像供学生导入。
> 磁盘策略：**所有大文件全部落在 D:\OpenHarmony，C 盘只承担 WSL 功能本体（约 0.1G）**。
> 版本依据：课程实验手册实验 1（OpenHarmony v5.0.0 Release / hispark_pegasus / ohos:mini）。

---

## 0. 磁盘与时间预算（先心里有数）

| 项目 | 位置 | 占用 | 耗时 |
|---|---|---|---|
| WSL2 功能本体 | C 盘（系统组件） | ~0.1G | 5 分钟 + 可能重启 |
| Ubuntu 系统 + 全部源码/工具链 | D:\OpenHarmony\WSL（虚拟磁盘） | ~12~15G | — |
| Ubuntu 安装包（rootfs tar.gz） | D:\OpenHarmony\download | ~0.7G | 10~30 分钟 |
| 拉取源码 + 工具链 | WSL 内部（即上面虚拟磁盘） | 9.3G | 40~90 分钟（看网速） |
| 编译产物 | WSL 内部 | ~1G | 首次 10~20 分钟 |
| 导出镜像 oh3861-env.tar | D:\OpenHarmony | ~5G | 10~15 分钟 |
| **D 盘合计** | | **约 25G**（余 60G，充裕） | **半天（留足网络时间）** |

前置自检（做之前花 2 分钟确认）：

1. Windows 10（版本 ≥1903 / 内部版本 ≥18362）或 Windows 11；
2. 主板虚拟化已开启：任务管理器 → 性能 → CPU → 看"虚拟化"是否为"已启用"。
   若"已禁用"，需进 BIOS 打开 VT-x/AMD-V（各品牌电脑按键不同，可搜"机型 + 开启虚拟化"）；
3. 能正常访问 gitee.com（浏览器打开试一下）。

## 1. 启用 WSL2（PowerShell 管理员）

以**管理员身份**打开 PowerShell，执行：

```powershell
wsl --install --no-distribution
```

- Windows 11 或较新的 Win10：这条会自动启用 WSL + 虚拟机平台 + 更新内核。
- 如果提示不认识 `--no-distribution` 参数（老版本 Win10），改用手动三条：

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
wsl --update
```

**重启电脑**（必须）。

重启后验证，管理员 PowerShell：

```powershell
wsl --status
```

看到"默认版本: 2"即 OK。这一步之后 C 盘占用约 0.1G，不会再增长。

---

## 2. 下载 Ubuntu 22.04 系统包（放到 D 盘）

> 注意：**不要**执行 `wsl --install Ubuntu-22.04`——那样 Ubuntu 会装进 C 盘。
> 我们用"下载系统包 + 导入到 D 盘"的方式，全程绕开 C 盘。

建目录（PowerShell）：

```powershell
mkdir D:\OpenHarmony\download
mkdir D:\OpenHarmony\WSL
```

下载 Ubuntu 22.04 的 WSL 专用系统包（约 325MB）：

- 官方源（浏览器直接开）：
  `https://cloud-images.ubuntu.com/wsl/jammy/current/ubuntu-jammy-wsl-amd64-ubuntu22.04lts.rootfs.tar.gz`
- 官方 SHA256 校验值：`1483cc5c1dce13064f774834cbffdff226559fd522a67a381a8ea77d63fb4109`（下载后可用 `certutil -hashfile 文件名 SHA256` 核对）；
- 下不动的话：用浏览器下载工具/IDM 断点续传，或把该 URL 丢进迅雷；
- 文件保存到 `D:\OpenHarmony\download\`。

**验证点**：文件后缀必须是 `.tar.gz`，大小 600~800MB。

---

## 3. 把 Ubuntu 导入到 D 盘（关键一步，不占 C 盘）

管理员 PowerShell：

```powershell
wsl --import oh3861 D:\OpenHarmony\WSL D:\OpenHarmony\download\ubuntu-jammy-wsl-amd64-ubuntu22.04lts.rootfs.tar.gz
```

- `oh3861` 是发行版名，以后就按这个名字管理；
- 第二个参数 `D:\OpenHarmony\WSL` 是虚拟磁盘的**落盘位置**——以后源码、工具链全部存在这里的一个 ext4.vhdx 文件里，占的是 D 盘。

验证 + 进入系统：

```powershell
wsl -l -v          # 应显示 oh3861，版本 2
wsl -d oh3861      # 进入 Ubuntu（默认是 root）
```

**验证点**：命令行变成 `root@机器名:/#` 样子，输入 `ls /` 能看到 Ubuntu 目录结构。

（可选，建议做）给系统建一个普通用户，后续更规范：

```bash
useradd -m -G sudo -s /bin/bash ohbuild
passwd ohbuild          # 设个记得住的密码
```

然后创建 `D:\OpenHarmony\set-default-user.txt` 记着这行配置，写入 WSL 的 `/etc/wsl.conf`（在 Ubuntu 里执行）：

```bash
tee /etc/wsl.conf <<'EOF'
[user]
default=ohbuild
EOF
```

回到 PowerShell 重启该发行版生效：`wsl --terminate oh3861`，再 `wsl -d oh3861`，应直接以 ohbuild 登录。
（嫌麻烦也可以一直用 root，教学自用没硬性障碍。）

## 4. Ubuntu 内基础配置（照实验手册实验 1，去冗余）

进入 `wsl -d oh3861` 后执行。

### 4.1 换华为云软件源 + 装基础工具

```bash
sudo cp -a /etc/apt/sources.list /etc/apt/sources.list.bak
sudo sed -i "s@http://.*archive.ubuntu.com@http://repo.huaweicloud.com@g" /etc/apt/sources.list
sudo sed -i "s@http://.*security.ubuntu.com@http://repo.huaweicloud.com@g" /etc/apt/sources.list
sudo apt-get update
sudo apt-get install -y git git-lfs ninja-build curl python3-pip zip unzip
sudo ln -sf /usr/bin/python3 /usr/bin/python
python --version    # 验证：Python 3.10.x
```

> Ubuntu 22.04 自带 Python 3.10，正好满足编译要求，不用另装。

### 4.2 装 repo 工具 + 配 git

```bash
curl https://gitee.com/oschina/repo/raw/fork_flow/repo-py3 -o /usr/local/bin/repo
chmod a+x /usr/local/bin/repo
git config --global user.name  "mayibo"
git config --global user.email "你的邮箱"
pip3 install -i https://repo.huaweicloud.com/repository/pypi/simple requests
```

（user.name/email 随便填一个能用即可，只为 repo 不报错。）

## 5. 拉取 hi3861 轻量系统源码（9.3G 的正主）

> 只拉 hispark_pegasus 这一份，**绝对不要碰 dayu200.xml 那条命令**。
> 源码放在 WSL 内部家目录（不要放 /mnt/d——跨盘 IO 很慢且有权限坑，虚拟磁盘本来就在 D 盘）。

```bash
mkdir -p ~/oh3861 && cd ~/oh3861
repo init -u https://gitee.com/openharmony/manifest -b refs/tags/OpenHarmony-v5.0.0-Release -m chipsets/hispark_pegasus.xml -g ohos:mini
repo sync -c        # 若中途报错，原样重跑这条，直到出现 finished successfully
repo forall -c 'git lfs pull'
```

**验证点**：`du -sh ~/oh3861` 约 3~5G；`ls ~/oh3861` 能看到 `build  kernel  device  base  foundation` 等目录。

### 5.1 装编译依赖 + 下载工具链（约 5G）

```bash
cd ~/oh3861
./build/build_scripts/env_setup.sh          # 装一系列编译依赖，装完按提示 source
source ~/.bashrc
bash build/prebuilts_download.sh            # 下载编译工具链，失败就重跑一次
```

**验证点**：`du -sh ~/oh3861` 涨到 9~10G，`ls ~/oh3861/prebuilts` 有内容。

## 6. 试编译（验证环境是否真通）

```bash
cd ~/oh3861
./build.sh --product-name wifiiot_hispark_pegasus --ccache --no-prebuilt-sdk
```

- 首次 10~20 分钟，结尾出现 `build successful` 即成功；
- 产物在这里（**注意：5.0 版本里烧录文件叫 `_burn.bin`，老教程里的 `_allinone.bin` 已改名**）：

ls ~/oh3861/out/hispark_pegasus/wifiiot_hispark_pegasus/Hi3861_wifiiot_app_burn.bin

把产物拷到 Windows 侧备用（WSL 里直接拷）：

**到这里，编译环境就闭环了。** 以后学生改代码 → 重跑第 6 步 → 拷出 bin → 烧录。

## 7. 烧录验证（HiBurn，Windows 侧）

1. 装串口驱动 CH341（实验手册给了 gitee 地址：
   `https://gitee.com/hihope_iot/docs/blob/master/HiSpark_WiFi_IoT/Software/tools/CH341SER.ZIP`）；
2. 下载 HiBurn（同仓库 Software/tools/HiBurn.exe），解压到 `D:\OpenHarmony\HiBurn\`；
3. USB 线连小车主板，设备管理器里确认出现 COM 口；
4. HiBurn：Select file 选刚才的 bin → 勾选 **Auto burn** → 点 **Connect** → **按小车板上的 RESET 键** → 自动开始烧录；
5. 烧完再按 RESET 复位运行。波特率默认 115200，稳定后可在下拉里改 921600 提速。

**终极验证**：先编译烧录 ex_8 的 TCP 服务端程序（代码包 `实验8-iot_tcp_server_ohcar`，把里面写死的
`WifiConnect("iQOO Z9 Turbo", "1873316779")` 改成你自己的热点），上电看双闪 → 连上热点后停止双闪 →
PC 上 `telnet 小车IP 8888` 发 `a` 看小车前进。

## 8. 打包分发给学生（环境跑通后做）

管理员 PowerShell：

```powershell
wsl --terminate oh3861
wsl --export oh3861 D:\OpenHarmony\oh3861-env.tar
```

得到约 4~5G 的 `oh3861-env.tar`（源码、工具链、编译配置、git 配置全在里面）。

**学生机使用方法（写进学生操作卡）：**

```powershell
# ① 开 WSL（一次性，管理员 PowerShell）
wsl --install --no-distribution
# 重启电脑

# ② 导入镜像（把 oh3861-env.tar 拷到 D 盘后）
mkdir D:\wsl
wsl --import oh3861 D:\wsl\oh3861 D:\oh3861-env.tar

# ③ 进入，直接编译
wsl -d oh3861
cd ~/oh3861
./build.sh --product-name wifiiot_hispark_pegasus --ccache --no-prebuilt-sdk
```

学生机磁盘要求：约 15G 空闲；无需 git/gitee，全程离线。

## 9. 常见报错对照表

| 症状 | 原因 | 处理 |
|---|---|---|
| `repo sync` 中途 error / 卡住 | gitee 网络波动 | 原样重跑 `repo sync -c`，可多次，直到 finished successfully |
| `prebuilts_download.sh` 下载失败 | 工具链源不稳 | 原样重跑该脚本（支持断点，已下载的会跳过） |
| 编译报 python 相关错误 | python 软链没做 | `sudo ln -sf /usr/bin/python3 /usr/bin/python` |
| WSL 启动报虚拟化错误 | BIOS 未开 VT-x | 任务管理器确认虚拟化状态，进 BIOS 开启 |
| `wsl --import` 后默认是 root | import 不保留默认用户 | 见第 3 步 `/etc/wsl.conf` 配置 |

## 10. 实测踩坑实录（2026-11-13 已全部走通，环境闭环）

以下问题在实际搭建中全部遇到并已解决，留档备查。**学生用导出镜像的话不涉及第 1~5 条**（工具链已就位），但第 6 条编译命令是通用的。

1. **工具链下载报 403（临时性拦截，已澄清）**：搭建当天 WSL 里跑官方脚本下载工具链时报 403，且脚本有 bug——下载失败仍打印"成功"，最后在 npm 环节崩溃。当时用"Windows 侧下载 + WSL 解压"绕过。**事后复测澄清：不是网络被拉黑**——同一台电脑、同样的 WSL 直连和热点，稍后重测该 URL 返回 200，可正常下载。真实原因定性为：官方脚本多线程高并发请求触发华为云 CDN 风控的**临时拦截**（过段时间自动解除），叠加脚本失败不报错，放大成了"死坑"。
   - **给以后重搭环境的人的建议**：先直接跑官方 `prebuilts_download.sh`，失败别慌，等几分钟重试；还不行再用备用方案——Windows 侧把 `prebuilts-pkgs\` 里的包（本机已留档 4.3G）拷过去解压，映射关系见 `car3861/extract_prebuilts.py`；
   - 顺手修的两个脚本坑：`env_setup.sh` 内藏交互式 y/n 询问（非交互环境会挂死，用 `yes y |` 管道自动应答或跳过）；报错静默问题（下载失败无提示）。
2. **缺 3 个 `current` 软链**：官方下载脚本会自动建，手动回填时要补：
   - `prebuilts/python/linux-x86/current → 3.11.4`
   - `prebuilts/build-tools/common/nodejs/current → node-v14.21.1-linux-x64`
   - nodejs 要 14.21.1 和 16.20.2 两个版本都解压到 `prebuilts/build-tools/common/nodejs/`
3. **riscv32 编译器不在 26 个包里**：单独下载
   `https://repo.huaweicloud.com/harmonyos/compiler/gcc_riscv32/7.3.0/linux/gcc_riscv32-linux-7.3.0.tar.gz`
   解压到 `prebuilts/gcc/linux-x86/riscv32/gcc_riscv32`，并把它的 `bin` 加入 PATH。
4. **系统依赖包**：`apt install bison ccache default-jdk flex ruby libssl-dev libtinfo5 genext2fs u-boot-tools mtools mtd-utils scons gcc-arm-none-eabi`
5. **Python 签名库**：`apt install python3-pycryptodome python3-ecdsa`，且 pycryptodome 装出来叫 `Cryptodome`，要建别名：
   `ln -s /usr/lib/python3/dist-packages/Cryptodome /usr/lib/python3/dist-packages/Crypto`
6. **编译命令两个坑**：
   - 5.0 里产品名是 `wifiiot_hispark_pegasus`（不是老教程的 `hispark_pegasus`，否则报 product not found）；
   - 必须加 `--no-prebuilt-sdk`（否则 SDK 预构建报 ability_base 缺失失败）。
7. **WSL 后台任务陷阱**：`nohup ... &` 后关掉终端，WSL 发行版会关机把任务杀掉。长时间编译要保持 WSL 会话在前台开着。
8. **编译速度**：hi3861 全量编译实测仅 19 秒（加了 ccache 后增量更快），"编译慢"的担心完全不成立——大头全在环境搭建。
| HiBurn 点 Connect 无反应 | COM 口被占用/驱动没装 | 关掉其他串口工具；重装 CH341 驱动 |
| HiBurn 烧录失败 | 没进烧录模式 | 点 Connect **之后**按板子 RESET 键 |
| 磁盘空间增长异常 | ext4.vhdx 只增不减 | 正常现象；删文件后可用 `wsl --shutdown` + `Optimize-VHD` 回收（可不做） |

## 10. 建议的推进顺序

1. **今天**：走完第 1~6 步（编译出第一个 bin）——环境闭环；
2. **然后**：第 7 步烧录小车真机验证（改一行车灯代码再编译烧一次，确认改动生效）；
3. **确认无误后**：第 8 步打镜像包；
4. 最后我再帮您出：学生操作卡（半页纸版）+ 把实验 8/13 协议对齐后的参考代码。
