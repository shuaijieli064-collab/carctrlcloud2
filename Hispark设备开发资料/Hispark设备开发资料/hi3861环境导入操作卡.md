# hi3861 环境导入操作卡（本机实测版）

> 适用场景：Windows 机器已具备 WSL2，通过老师导出的整盘镜像 `oh3861-student.vhdx`（34.84G）离线获得完整 OpenHarmony 5.0.0 hi3861 编译环境，**无需下载源码、无需拉工具链**。
>
> 本卡所有数字取自 2026-11-14 本机实测：WSL 客户端 2.7.3.0、E 盘顺序读取 65.6 MB/s、D 盘可用 273.70G、镜像 37,404,803,072 字节。

---

## 0. 前置检查（本机已通过，留档备查）

| 检查项 | 本机实测 | 要求 |
|---|---|---|
| WSL 客户端版本 | 2.7.3.0（`C:\Program Files\WSL\wsl.exe`） | ≥ 2.0，才支持 `--vhd` |
| WSL 服务 | `WslService` Running | 必须运行 |
| 目标盘文件系统 | D: NTFS，可用 273.70G | NTFS，可用 ≥ 40G |
| 镜像大小 | 34.84G / 37,404,803,072 字节 | 与老师记录一致 |
| 镜像合法性 | 文件头 `vhdxfile`，属性 Archive | 非只读、非损坏 |
| 名称冲突 | 已有 `docker-desktop`、`Ubuntu-24.04`，无 `oh3861` | 无同名发行版 |

其他机器的自检口径：`wsl --version` 有输出即已启用；`wsl -l -v` 里没有 `oh3861` 即可。

## 1. 接入移动硬盘并确认镜像

1. 插入移动硬盘（TOSHIBA EXT），资源管理器出现 **E:** 盘；
2. 确认 `E:\oh3861-student.vhdx` 存在，右键属性大小应为 **37,404,803,072 字节（≈ 34.84G）**；
3. **不需要先拷到 D 盘**。`wsl --import --vhd` 本身就是把 vhdx 复制到目标目录，预拷贝会让 D 盘峰值涨到 69.7G（两份 35G）、耗时翻倍。E 盘原件在导入后原样保留，本身就是备份。

---

## 2. 导入发行版（1 条命令，10~20 分钟）

打开 PowerShell（普通权限即可），执行：

```powershell
wsl --import oh3861 D:\OpenHarmony\WSL "E:\oh3861-student.vhdx" --vhd
```

参数含义：

- `oh3861` —— 发行版名，与老师文档里的命令保持一致，**不要改名**；
- `D:\OpenHarmony\WSL` —— 虚拟磁盘落盘目录，不存在会自动创建；
- `"E:\oh3861-student.vhdx"` —— 源镜像，路径含空格时须加引号；
- `--vhd` —— **必带**。漏掉会按 tar 格式解析，报「不支持该文件」。

预期表现：命令执行后长时间无输出（属正常，正在搬运 35G），完成后直接回到提示符。若中途 Ctrl+C 中断，删除 `D:\OpenHarmony\WSL` 后重来。

执行期间三条禁令：**不要拔移动硬盘**、**不要执行 `wsl --shutdown`**、**不要同时启动 Docker Desktop 做重操作**。

## 2.5 首次使用必做：补 riscv32 工具链 PATH（镜像已知缺陷）

**现象**：导入后第一次编译，全部 72 个目标报同一个错：

```
ccache: error: Could not find compiler "riscv32-unknown-elf-gcc" in PATH
[OHOS ERROR] Reason: COMPILE Failed! ... Error Type: Ninja build error  Code: 4000
```

**原因**：工具链文件是齐全的（`prebuilts/gcc/linux-x86/riscv32/gcc_riscv32/bin/` 下有 `riscv32-unknown-elf-gcc` 等全套），但把工具链加入 `PATH` 的配置**在镜像里缺失** —— 官方 `build/build_scripts/env_setup.sh` 会向 `~/.bashrc` 追加 7 条 `export PATH=...`，本镜像的 `~/.bashrc` 里一条都没有。与拔插 U 盘、磁盘无关。

**修复**（在 oh3861 终端执行一次，永久生效）。官方 `env_setup.sh` 追加的 7 条合并成一条完整 PATH 即可：

```bash
FULL="/root/oh3861/prebuilts/gcc/linux-x86/riscv32/gcc_riscv32/bin:/root/oh3861/prebuilts/clang/ohos/linux-x86_64/llvm/bin:/root/oh3861/prebuilts/build-tools/linux-x86/bin:/root/oh3861/prebuilts/build-tools/common/nodejs/current/bin:/root/.local/bin"

# ① 全局（登录 shell / 脚本 / 自动化调用都要）
printf 'export PATH="%s:$PATH"\n' "$FULL" > /etc/profile.d/ohos_env.sh
chmod 644 /etc/profile.d/ohos_env.sh

# ② 交互式 shell（直接 wsl -d oh3861 进去手敲命令）
echo "export PATH=\"$FULL:\$PATH\"" >> ~/.bashrc
```

验证（**两条都要过**）：

```bash
bash -lc 'node -v; gn --version; ninja --version; riscv32-unknown-elf-gcc --version | head -1'
# 期望：v14.21.1 / 2021 (1cdd270b) / 1.12.0 / GCC 7.3.0
```

> **为什么必须分两处写**：
> - Ubuntu 的 `.bashrc` 第 6 行是 `[ -z "$PS1" ] && return`，**非交互 shell 直接返回**，追加的 PATH 不生效 —— 所以脚本/自动化调用要落到 `/etc/profile.d/`；
> - 反过来，`wsl -d oh3861` 打开的是**交互式非登录** shell，只读 `.bashrc`、**不读** `/etc/profile.d/` —— 所以手敲时要有 `.bashrc` 那份。
> 只写其中一处，另一半场景就会再次报 `Could not find compiler`。

> **另一个坑：`export PATH=` 的值必须用双引号包住**。WSL 会把 Windows 的 PATH（含 `Program Files` 等带空格的路径）拼进 `$PATH`，不加引号会报一串 `export: 'Files/Microsoft': not a valid identifier`，且 PATH 只被截断赋值 —— 表面上命令没失败，实际埋下隐患。

**附带的 shell 问题**：构建开头提示 `Your system shell isn't bash`，因为 `/bin/sh` 指向 dash。改为 bash：

```bash
echo 'dash dash/sh boolean false' | sudo debconf-set-selections
sudo DEBIAN_FRONTEND=noninteractive dpkg-reconfigure dash
ls -l /bin/sh     # 应显示 /bin/sh -> bash
```

## 3. 验证（3 分钟，缺一不可）

```powershell
wsl -l -v
```

预期：出现 `oh3861   Stopped   2`（版本必须是 2）。

```powershell
wsl -d oh3861
```

进入后默认是 **root**（`wsl --export/--import` 不保留默认用户，属正常现象）。依次执行：

```bash
cd ~/oh3861 && ls
# 应看到 build.sh  kernel  vendor  applications  prebuilts  device  foundation 等目录

./build.sh --product-name wifiiot_hispark_pegasus --ccache --no-prebuilt-sdk
# 首次约 30 秒~2 分钟（镜像内已带 ccache），结尾出现 build success

ls out/hispark_pegasus/wifiiot_hispark_pegasus/*.bin
# 应看到 Hi3861_wifiiot_app_burn.bin
```

三条都对上，编译环境即闭环。

> 注意：5.0 版本的烧录文件叫 `_burn.bin`，网上老教程写的 `_allinone.bin` 已改名。以 `out/` 目录实际文件名称为准。

## 4. 烧录工具（此步需要网络）

仅在需要把固件刷进板子时做：

1. **CH341 串口驱动**：`https://gitee.com/hihope_iot/docs/blob/master/HiSpark_WiFi_IoT/Software/tools/CH341SER.ZIP`，解压后以管理员运行 `SETUP.EXE`；
2. **HiBurn 烧录工具**：同仓库 `Software/tools/HiBurn.exe`，解压到如 `D:\OpenHarmony\HiBurn\`；
3. USB 线连接小车主板，设备管理器「端口」下应出现 `USB-SERIAL CH340 (COMx)`；
4. 固件从 WSL 拷到 Windows：

```bash
cp ~/oh3861/out/hispark_pegasus/wifiiot_hispark_pegasus/Hi3861_wifiiot_app_burn.bin /mnt/d/OpenHarmony/firmware/
```

5. HiBurn 操作顺序：`Select file` 选 bin → 勾 `Auto burn` → 点 `Connect` → **再按板子的 RESET 键** → 自动开始烧录；
6. 烧完再按一次 RESET 复位运行。波特率默认 115200，稳定后可改 921600 提速。

## 5. 日常使用（每次开课/改代码的最小动作）

```powershell
wsl -d oh3861
```

```bash
cd ~/oh3861
./build.sh --product-name wifiiot_hispark_pegasus --ccache --no-prebuilt-sdk
cp out/hispark_pegasus/wifiiot_hispark_pegasus/Hi3861_wifiiot_app_burn.bin /mnt/d/OpenHarmony/firmware/
```

改代码 → 重编译（20~60 秒）→ 拷 bin → HiBurn 烧录。循环就这么长。

**关键约束**：源码必须留在 WSL 内部 `~/oh3861`，不要放到 `/mnt/d` 下编译——跨盘 9p IO 会慢数倍，且存在权限与软链接问题。

## 6. 故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译报 `ccache: error: Could not find compiler "riscv32-unknown-elf-gcc" in PATH` | 镜像缺 PATH 配置 | 见 **2.5 节**，一次性修复 |
| `wsl --import` 报「不支持该文件」 | 漏了 `--vhd` | 补上 `--vhd` 重跑 |
| 报「文件名、目录名或卷标语法不正确」 | 目标目录已存在且非空 | 换目录名或清空后重试 |
| 报「另一个安装正在运行」 | WSL 自身在升级 | 等 3~5 分钟后重试 |
| 报 `SHARING_VIOLATION` | vhdx 被占用 | 确认没有其他 WSL 会话在用该文件；重启电脑后重试 |
| 导入后 `wsl -d oh3861` 进不去 | 发行版状态异常 | `wsl --terminate oh3861` 后重进；仍不行则 `wsl --unregister oh3861` 重新导入 |
| 编译报 product not found | 产品名写错 | 必须是 `wifiiot_hispark_pegasus`，不是 `hispark_pegasus` |
| 编译报 SDK 预构建失败 | 漏了 `--no-prebuilt-sdk` | 补上该参数 |
| 编译报 python 相关错误 | python 软链缺失 | 镜像内已配好；若自行重搭需 `sudo ln -sf /usr/bin/python3 /usr/bin/python` |
| 磁盘空间暴涨 | 虚拟磁盘只增不减（本机为 `D:\OpenHarmony\WSL\oh3861-student.vhdx`） | 正常现象；`wsl --shutdown` 后可用 `Optimize-VHD` 回收（可不做） |
| HiBurn 点 Connect 无反应 | COM 口被占用或驱动未装 | 关掉其他串口工具；重装 CH341 驱动 |
| HiBurn 烧录失败 | 未进入烧录模式 | 先点 Connect，**再**按板子 RESET |

## 7. 回滚与清理

```powershell
wsl --unregister oh3861     # 永久删除该发行版及其 35G 虚拟磁盘，不进回收站
```

删除后如需重来，回到第 2 步重新导入即可（E 盘镜像仍在）。

清理 D 盘目录：`Remove-Item -Recurse -Force D:\OpenHarmony\WSL`（仅在 unregister 之后）。

## 8. 与既存环境的并存关系

本机原有 `Ubuntu-24.04`（C 盘，用于 Claude Code 等）**不受本流程任何影响**，两套发行版完全独立：

| | Ubuntu-24.04 | oh3861 |
|---|---|---|
| 用途 | 通用开发 / Claude Code | OpenHarmony hi3861 编译 |
| 落盘 | `C:\Users\lsj\AppData\Local\wsl\{guid}` | `D:\OpenHarmony\WSL` |
| 进入 | `wsl -d Ubuntu-24.04` | `wsl -d oh3861` |

**不要**对 `Ubuntu-24.04` 执行 `--unregister`；**不要**随意 `wsl --shutdown`（会连带关闭 Docker Desktop 的 WSL 后端）。
