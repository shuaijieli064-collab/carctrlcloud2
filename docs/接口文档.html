通道A：TCP 直连控制接口（PC:8888）

提供方：simulator/car_server.py（--port 可改） · 调用方：APP TcpClient.ets · 状态：隐藏 DEBUG 模式（CarConfig.ENABLE_TCP_DEBUG），帧格式与云端模式共用 CommandProtocol 编解码。

项目约定
传输TCP 长连接，JSON 文本帧 + \n 分帧（UTF-8）
寻址模拟器 10.0.2.2:8888；真机填电脑局域网 IP（如 10.234.215.153:8888）
容错非法帧解析返回 error 帧，连接不中断（decode → null 兜底）

上行（APP → 车）

type帧示例说明
move{"type":"move","seq":12,"lx":0.50,"ly":-1.00,"ts":1760000000000} lx 横轴转向（左负右正），ly 纵轴前后（下负上正），取值 [-1,1]
stop{"type":"stop","seq":13}急停，速度归零
ping{"type":"ping","seq":14}连通性探活

下行（车 → APP）

type帧示例说明
ack{"type":"ack","seq":12,"ok":true}命令受理回执（seq 对应上行）
pong{"type":"pong","seq":14}ping 应答
state{"type":"state","speed":0.60,"battery":87,"heading":90,"x":1.2,"y":3.4} 周期状态流（100ms）：速度 m/s、电量 %、朝向 °、坐标 m
error{"type":"error","msg":"..."}非法/缺字段帧的错误响应

通道B：MQTT 平台接口 — 本地模拟 broker（PC:1883，IoTDA 风格）

提供方：simulator/mqtt_broker.py（自研最小 MQTT broker，另挂俯视图 WS :8899） · 调用方：车端 car_mqtt_device.py（设备身份）、APP MqttClient.ets + IotBridge.ets（应用身份）· 鉴权协议实现：mqtt_protocol.py。

项目约定
设备/应用注册表DEVICE_REGISTRY（默认 car_001）、APP_REGISTRY（默认 app_controller），各自独立密钥
clientId{id}_{Unix秒}
username{id}
passwordBase64( HMAC-SHA256( key=secret, msg="HMAC-SHA256 {id} {ts}" ) )（教学模板，注意与真平台模板不同）
拒绝码CONNACK code=4 = 用户名或密码错误（密钥不匹配 / 身份不在注册表）

Topic 表

方向Topic 模板说明
设备订阅（收命令）$oc/devices/{device_id}/sys/commands/## 通配 request_id 与 command_name 两段
应用发布（下命令）$oc/devices/{device_id}/sys/commands/request_id={rid}/command_name={name} rid 唯一（时间戳+随机数）；name 大小写不敏感
设备发布（属性上报）$oc/devices/{device_id}/sys/properties/report周期上报
设备发布（命令响应）$oc/devices/{device_id}/sys/commands/response/request_id={rid}应用侧据此确认执行结果

命令 payload（body 均为 JSON 对象）

// move —— 发布到 command_pub_topic
{"service_id":"Car","command_name":"move","paras":{"lx":0.50,"ly":-1.00}}
// stop / ping
{"service_id":"Car","command_name":"stop","paras":{}}
{"service_id":"Car","command_name":"ping","paras":{}}

// 属性上报
{"services":[{"service_id":"Car","properties":{"speed":0.6,"battery":87,"heading":90,"x":1.2,"y":3.4}}]}

// 命令响应（车端 → rid 对应 topic）
{"result_code":0}
命令参数校验
movelx, ly：decimal，[-1,1]，必填缺字段 → 拒绝执行（用例8验证）
stop无—
ping无—

通道C：MQTT TLS 接口 — 华为云真平台车端（:8883）

服务方：华为云 IoTDA 标准版实例（1dc089e08c.st1.iotda-device.cn-north-4.myhuaweicloud.com:8883，TLS）· 调用方：车端 car_mqtt_device.py --platform real（配置自动加载自 iotda_config.json）· topic 与命令结构同通道B，鉴权模板不同（官方规范）。

项目约定
clientId{deviceId}_0_{sig}_{ts}，ts=UTC YYYYMMDDHH；sig=0 不校验时间戳 / 1 校验（±10min 窗）
username{deviceId}（形如 {产品ID}_car_001）
passwordHMAC-SHA256( key=ts字符串, msg=设备secret ) 的 hex 小写（非 Base64）
心跳自研客户端自动 PINGREQ（keepalive/2 间隔）
互斥同一 deviceId 只允许一条连接：重复上线会互踢（排障高频坑）
会话空窗设备重连瞬间平台可能仍把命令路由给旧死会话 → IOTDA.014111 超时，重发即可

通道D：应用侧 HTTPS 接口 — APP 直连华为云（:443）

服务方：华为云 IoTDA 应用接入端点（1dc089e08c.st1.iotda-app.cn-north-4.myhuaweicloud.com:443）· 调用方：APP HuaweiCloudClient.ets · 鉴权：IAM 子用户 AK/SK + V11-HMAC-SHA256 请求签名（每请求独立签名，无 token 过期问题）。

公共：签名规则（摘要）

Authorization: V11-HMAC-SHA256 Credential={AK}/{YYYYMMDD}/{region}/iotdm,
               SignedHeaders=content-type;host;x-project-id;x-sdk-date, Signature={hex}

派生密钥：  PRK = HMAC-SHA256(key=AK,      msg=SK)
            DK  = hex( HMAC-SHA256(key=PRK, msg=info + 0x01) )      // info = "{YYYYMMDD}/{region}/iotdm"
签名字符串： CanonicalRequest = "POST\n{URI尾带斜杠}\n\n{规范Headers}\n{SignedHeaders}\n{SHA256(body)}"
            StringToSign     = "V11-HMAC-SHA256\n{UTC YYYYMMDDTHHMMSSZ}\n{info}\n{SHA256(CR)}"
            Signature        = HMAC-SHA256(key=utf8(DK), msg=StringToSign)
必带头：    X-Project-Id: {项目ID}   X-Sdk-Date: {UTC时间}   Content-Type: application/json
V11-HMAC-SHA256 是 标准版 IoTDA 实例专属签名变体（HKDF 派生 + 服务名 iotdm），与普通 OpenAPI 的 SDK-HMAC-SHA256 不同。两种都试过 401 后从官方 SDK 源码逆向核实。

接口 1：查询设备影子 GET

GET /v5/iot/{project_id}/devices/{device_id}/shadow
→ 200 {"device_id":"...","shadow":[{"service_id":"Car","reported":{"properties":{...}},"desired":{}}]}

用途：APP 以 1s 轮询（CarConfig.CLOUD_POLL_INTERVAL_MS）替代 MQTT 订阅，获取 speed/battery/heading/x/y。
特点：读缓存，设备离线也可查询（返回最后一次上报值）。

接口 2：下发同步设备命令 POST

POST /v5/iot/{project_id}/devices/{device_id}/commands
body: {"service_id":"Car","command_name":"move","paras":{"lx":0.50,"ly":-1.00}}
→ 200 {"response":{"result_code":0}}          // 车端实时回执
→ 失败: {"error_code":"IOTDA.01xxxx","error_msg":"..."}

用途：move / stop / ping 全部走此接口（MQTT 设备唯一可用命令接口）。
约束：设备必须在线；body 缺 service_id / paras 校验失败 → 400。

接口 3：下发异步设备命令 POST · 不适用本项目

POST /v5/iot/{project_id}/devices/{device_id}/async-commands
body: {"service_id":"Car","command_name":"move","paras":{...},
       "expire_time":0,"send_strategy":"immediately"}   // send_strategy 必填: immediately | delay

结论：仅支持 LwM2M/CoAP 设备，MQTT 设备调用返回 IOTDA.014114（实测）。
保留说明：该方法 sendCommandAsync 仍留在代码中作教学对照。

通道E：俯视图 WebSocket 接口（:8889 / :8899，只看不控）

提供方：car_server.py（:8889，TCP 直连模式）/ mqtt_broker.py --ws-port（:8899，IoT 模式）· 调用方：浏览器页面 simulator/webview.html（自研 RFC6455 最小 WS 实现，纯标准库）。

项目约定
连接ws://{host}:{port}/（HTTP Upgrade 握手）
下行帧100ms 一次 {"type":"state","speed":..,"battery":..,"heading":..,"x":..,"y":..}
过滤页面侧 if (m.type !== "state") return; —— 帧必须含 type:"state"，否则被丢弃
权限只广播状态，不接受控制指令（"只看不控"安全设计）

附录1：错误码实录（本项目排障沉淀）

错误含义处置
CONNACK code=4MQTT 鉴权失败（用户名/密码不匹配，或身份不在注册表）核对 secret、鉴权模板（local 与 real 模板不同）
400 IOTDA.000006请求体校验失败（如 async-commands 缺 send_strategy）按 error_msg 中 Field 名补齐字段
400 IOTDA.014114该 API 不支持 MQTT 设备MQTT 设备改走同步命令接口 /commands
403（同步命令）设备离线（影子可读缓存，命令要求在线）先让车端上线再下发；读 403 另查 IAM 权限
401（HTTPS）签名错误（普通 SDK-HMAC-SHA256 ≠ V11）/ AK·SK 不对确认用 V11 模板 + X-Project-Id；核对 credentials.csv
IOTDA.014111命令超时：设备重连空窗期命令路由到旧死会话重发命令即可
WinError 10061目标地址端口无监听（脚本没跑 / 地址错 / 同 deviceId 被踢）netstat 查监听 + 日志定位
